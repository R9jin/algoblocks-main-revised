# Workspace bug fixes

1. `PythonCodeEditor.jsx` - Monaco now uses `automaticLayout: true`. The editor sits in a dock panel that is `display:none` while another tab is active and is resized by the splitters, so it stayed 0x0 / stale-sized.
2. `MainApp.jsx` / `ActivityApp.jsx` - the delayed `resize()` calls (50 ms / 300 ms) now re-read the ref and use optional chaining, so closing a tab or unmounting inside that window no longer throws.
3. `MainApp.jsx` `closeTab` - no longer calls `setActiveTabId` / `createInitialTab` inside a `setTabs` updater (React may run updaters twice, which could leave the active tab pointing at a discarded tab).
4. `MainApp.jsx` `handleClear` - resets `isEditingCode` to false. Before, after typing Python and pressing Clear, new blocks never updated the Python panel.
5. `MainApp.jsx` `handleDeleteItem` - when the deleted project is open in a tab, the tab is fully reset (Python text, blocklyJson, analysis). Before, the deleted blocks could reappear when the Blocks panel remounted.
6. `MainApp.jsx` `handleImportJson` - rejects JSON that is not a Blockly workspace (it used to wipe the workspace and still show "imported successfully") and guards a missing `pythonCode`.
7. `BlocklyWorkspace.jsx` - `global` lines written in Raw Code blocks (or synced from Python) are now kept; only the ones Blockly auto-adds are stripped.
8. `DockableWorkspace.jsx` - splitters use pointer events (touch/pen work) and clean up listeners on unmount. `resize()` only takes focus when nothing else has it.
9. Removed leftovers: `DockedBottomPanel.jsx`, `temp_mainapp.css`, `PatternSignals`, `analyzer.py.orig`.

10. `MainApp.jsx` (also serves the admin Pipeline page) - live analysis no longer stops updating while you type or edit blocks. The analysis effect only ran while `isEditingCode` was true, and the automatic Python -> Blocks sync turns that flag off ~500 ms after typing, which cancelled the pending 800 ms analysis timer; the regenerated block code usually equals the typed text, so the Blockly path never re-triggered it. Analysis is now one debounced effect on the tab's `pythonCode` (deduped per tab), so typing, pasting and block edits all trigger it.
11. `ActivityApp.jsx` - live analysis no longer depends on `isOnline` (analysis runs in the local Pyodide worker, so a flaky network flag could silently stop it).
12. Analyzer - BFS with a plain-list `visited` (`if not neighbor in visited` / `visited.append(neighbor)`): the membership check is O(V) per check, O(V*E) in total, but was shown as O(V+E). Total time is now `O(V^2+V*E)` with a list queue (`pop(0)`) or `O(V*E)` with a deque; `visited.append` space is O(V) (not O(V+E)) because the append is guarded by the membership test; the entry-point call row now shows the same total as the badge. Set/deque BFS and all 273 ground-truth programs are unchanged. Tests added in `tests/test_symbol_and_graph_rules.py`.
13. `formatters.js` - `formatComplexity` superscripted the `+` after an exponent, so `O(V^2+E)` showed as `O(V²⁺E)`. Only the exponent is superscripted now.
14. Templates `graph/dfs_undirected` and `graph/dfs_directed` - `visited` is now a set (`set_create_empty` / `set_add`) instead of a list, so `neighbor in visited` is O(1) and the traversal is a true O(V+E). BFS templates are unchanged: they use the Queue blocks, whose dequeue is `list.pop(0)` (O(V) each), so BFS stays O(V^2+E) even with a set; a true O(V+E) BFS needs a deque block.
15. New Deque blocks (Stacks & Queues): `create empty deque`, `create deque from list`, `popleft and get front of deque`, `popleft from deque` (`BlocklyWorkspace.jsx` block defs, Python generators, toolbox; `blockly_ast.py` converts `deque()`, `deque(x)`, `q.popleft()` both as expression and statement; `blockGlossary.js` entries). The generator adds `from collections import deque` itself, and identical import lines are de-duplicated so a Raw Code import does not appear twice. Templates `graph/bfs_undirected` and `graph/bfs_directed` now use a visited set (`set_create_empty` / `set_add`) and a deque (`deque_from_list` / `deque_popleft`), so the analyzer reports `O(V+E)` for all four graph templates. Tests added in `tests/test_symbol_and_graph_rules.py`.
