# Workspace bug fixes

1. `PythonCodeEditor.jsx` - Monaco now uses `automaticLayout: true`. The editor sits in a dock panel that is `display:none` while another tab is active and is resized by the splitters, so it stayed 0x0 / stale-sized.
2. `MainApp.jsx` / `ActivityApp.jsx` - the delayed `resize()` calls (50 ms / 300 ms) now re-read the ref and use optional chaining, so closing a tab or unmounting inside that window no longer throws.
3. `MainApp.jsx` `closeTab` - no longer calls `setActiveTabId` / `createInitialTab` inside a `setTabs` updater (React may run updaters twice, which could leave the active tab pointing at a discarded tab).
4. `MainApp.jsx` `handleClear` - resets `isEditingCode` to false. Before, after typing Python and pressing Clear, new blocks never updated the Python panel.
5. `MainApp.jsx` `handleDeleteItem` - when the deleted project is open in a tab, the tab is fully reset (Python text, blocklyJson, analysis). Before, the deleted blocks could reappear when the Blocks panel remounted.
6. `MainApp.jsx` `handleImportJson` - rejects JSON that is not a Blockly workspace (it used to wipe the workspace and still show "imported successfully") and guards a missing `pythonCode`.
7. `BlocklyWorkspace.jsx` - `global` lines written in Raw Code blocks (or synced from Python) are now kept; only the ones Blockly auto-adds are stripped.
8. `DockableWorkspace.jsx` - splitters use pointer events (touch/pen work) and clean up listeners on unmount. `resize()` only takes focus when nothing else has it.
9. Removed leftovers: `DockedBottomPanel.jsx`, `temp_mainapp.css`, `PatternSignals`, `analyzer.py.orig`.

10. `MainApp.jsx` (also serves the admin Pipeline page) - live analysis no longer stops updating while you type or edit blocks. The analysis effect only ran while `isEditingCode` was true, and the automatic Python -> Blocks sync turns that flag off ~500 ms after typing, which cancelled the pending 800 ms analysis timer; the regenerated block code usually equals the typed text, so the Blockly path never re-triggered it. Analysis is now one debounced effect on the tab's `pythonCode` (deduped per tab), so typing, pasting and block edits all trigger it.
11. `ActivityApp.jsx` - live analysis no longer depends on `isOnline` (analysis runs in the local Pyodide worker, so a flaky network flag could silently stop it).
12. Analyzer - BFS with a plain-list `visited` (`if not neighbor in visited` / `visited.append(neighbor)`): the membership check is O(V) per check, O(V*E) in total, but was shown as O(V+E). Total time is now `O(V^2+V*E)` with a list queue (`pop(0)`) or `O(V*E)` with a deque; `visited.append` space is O(V) (not O(V+E)) because the append is guarded by the membership test; the entry-point call row now shows the same total as the badge. Set/deque BFS and all 273 ground-truth programs are unchanged. Tests added in `tests/test_symbol_and_graph_rules.py`.
13. `formatters.js` - `formatComplexity` superscripted the `+` after an exponent, so `O(V^2+E)` showed as `O(V²⁺E)`. Only the exponent is superscripted now.
14. Templates `graph/dfs_undirected` and `graph/dfs_directed` - `visited` is now a set (`set_create_empty` / `set_add`) instead of a list, so `neighbor in visited` is O(1) and the traversal is a true O(V+E). BFS templates are unchanged: they use the Queue blocks, whose dequeue is `list.pop(0)` (O(V) each), so BFS stays O(V^2+E) even with a set; a true O(V+E) BFS needs a deque block.
15. New Deque blocks (Stacks & Queues): `create empty deque`, `create deque from list`, `popleft and get front of deque`, `popleft from deque` (`BlocklyWorkspace.jsx` block defs, Python generators, toolbox; `blockly_ast.py` converts `deque()`, `deque(x)`, `q.popleft()` both as expression and statement; `blockGlossary.js` entries). The generator adds `from collections import deque` itself, and identical import lines are de-duplicated so a Raw Code import does not appear twice. Templates `graph/bfs_undirected` and `graph/bfs_directed` now use a visited set (`set_create_empty` / `set_add`) and a deque (`deque_from_list` / `deque_popleft`), so the analyzer reports `O(V+E)` for all four graph templates. Tests added in `tests/test_symbol_and_graph_rules.py`.
16. `BlocklyWorkspace.jsx` Functions flyout - a function that returns a value (like `dfs_undirected`) only got a value-style call block (with an output tab), which cannot sit on its own, so it could not be run directly. The flyout now also offers the statement-style call block (`procedures_callnoreturn`) for every function that returns a value, the same block the graph templates use. (Blockly 12 returns flyout items as plain objects, so the code handles both objects and XML.)
17. `DockableWorkspace.jsx` / `DockableWorkspace.css` - dock tabs (Console, Python, Blocks, Complexity, ...) could not be dragged on touch screens or in Chrome's device mode, because they only used HTML5 drag-and-drop, which never fires for touch. Tabs now also support a press-and-hold (~0.25 s) then slide with touch/pen: a floating tab label follows the finger, the region under it highlights (the center region still has edge zones), and on phone widths a drop bar (Workspace / Bottom / Left / Right / Top) appears so a tab can be moved to any region, including empty ones. A quick swipe still scrolls the tab bar and a tap still selects the tab. Mouse drag is unchanged. The native long-press drag Android Chrome starts on `draggable` elements is cancelled so it cannot fight the new path. The drop logic is shared (`commitDrop`).
18. `CallGraphVisualizer.jsx` - the call graph could only be panned with a mouse. It now uses pointer events: one finger pans, two fingers pinch-zoom around their midpoint (`touch-action: none` so the page does not scroll instead).
19. Per-line explanations were too long and repeated themselves (the fixed-bound "scored O(n), strictly O(1)" caveat appeared up to five times per loop line, plus duplicated count/space text). Python explainer: removed the "Why a fixed bound still shows O(n)" insight, trimmed the same caveat out of the "Counting iterations" theory note, shortened the Local Analysis wording to "(a fixed bound, strictly O(1))" and tightened the "Strict asymptotic analysis" paragraph, which stays as the one place that explains it (tests rely on it). "A O(n) step" is now "An O(n) step". UI: "Educational Insight" is collapsed behind a "Learn more" toggle; when a line's space is O(1) the space explanation is collapsed under "Why is it O(1)?" (its chart is still shown); (the time and space charts were briefly collapsed/merged too, but that was reverted: both charts are always shown side by side as before). Analyzer copy synced to `api/analyzer_diagnostics`.
20. Symbolic scoring is now explained in general, not just for `for` loops. A new "Symbolic scoring" note (`growth_insight.symbolic_scoring_note`, appended to the overall explanation) says AlgoBlocks may treat parts of the code symbolically instead of applying strict asymptotic analysis, that fixed values are read as examples of an input size `n`, and that the feedback is then a generalized learning example that can differ from the strict complexity of the exact code; it lists each place it applied: fixed `range(...)` bounds, a script-level variable holding a fixed number used as a loop bound (`n = 10`), and calls to a scaling function with literal arguments (`fact(5)`). Programs with a real input size get no note. The per-line "Strict asymptotic analysis" paragraph now also says the fixed bound is "scored symbolically". Test added in `tests/test_theoretical_analysis.py`; analyzer copy synced.

## Workspace / Activity / Pipeline sweep

21. `MainApp.jsx` `submitSave` - **Edit details** on a sidebar project/template wrote the *active tab's* Python into that record (local copy and cloud), pairing the item's blocks with unrelated code. A metadata-only edit now keeps the record's own `pythonCode`.
22. `MainApp.jsx` `handleImportJson` - the check from item 6 only rejected non-objects, so `{}`, `{"a":1}` or an array still wiped the workspace and said "imported successfully". It now requires a real Blockly workspace (`{ blocks: { ... } }`); a Python-only AlgoBlocks export (`blocklyJson: {}`) is still accepted. Also: importing no longer keeps the tab's old `currentLoadedId` (the next Save silently overwrote the project the tab had been opened from), and a closed Blocks panel now gives an error toast instead of doing nothing.
23. `MainApp.jsx` `handleClear` - did nothing (but closed the dialog) when the Blocks panel was closed. It now always resets the tab. The per-tab "already auto-synced this text" / "last analysed" / "typed" bookkeeping is also forgotten on Clear, on deleting the open project, on closing a tab and when a template replaces an empty tab; before, re-pasting the same Python after Clear never synced to blocks.
24. `MainApp.jsx` `closeTab` - an edited tab was discarded with one click. It now asks first (not in pipeline mode). `executeSidebarLoad` also treats a tab with typed, not-yet-synced Python as non-empty instead of replacing it.
25. `MainApp.jsx` - Monaco markers were lost whenever the Python panel remounted (panel moved/reopened) and "possible bug" lint notes were drawn as red errors; markers are re-applied on mount and non-blocking notes are warnings. `showToast` timers no longer cut a newer toast short. The analysis-epoch map no longer grows for the whole session. The emergency localStorage snapshot no longer stores the (large, rebuilt-anyway) analysis result, which could exceed the quota and silently disable recovery. Run timeout also stops the output flush timer.
26. `ActivityApp.jsx` `runTestCases` - **scoring**: the functional-test denominator was counted while looping, so a run cut short (timeout, Stop, output flood) was graded on the tests reached, not all of them (3 passed of 6, stopped at test 4 => 3/4 instead of 3/6), inflating TSR/AES and able to mark the activity as passed. The denominator is now the real number of functional tests.
27. `ActivityApp.jsx` - saves from handlers registered once (page unload, Ctrl+S, "back online", unmount cleanup) captured the first render's `totalTests` (0) and wrote "0 tests" over the real record. They now read `totalTestsRef`.
28. `ActivityApp.jsx` - console output was not live from the second Run onward (and after any `input()`): `clearInterval` left the dead id in `renderIntervalRef`, and the output handler only starts a flush timer when that ref is empty. A `clearRenderInterval()` helper nulls it; it is also cleared on timeout and on unmount.
29. `ActivityApp.jsx` - the Test Cases cards read pass/fail by searching the live console text, so Clear, Run Code, or a program that prints "Test 1: PASSED" changed or wiped them. They read `testRunOutput` (the last Submit run) instead.
30. `ActivityApp.jsx` - several bare `JSON.parse` of the stored `user` (page wrapper, tour effect, reward/progress code, Restart) could throw on a corrupted entry, crashing the page or skipping the reward modal; they use `readStoredUser()`. Restart's reset flag now has a safety timer so autosave cannot stay disabled if Restart throws. The activity page now draws error/warning markers in the Python editor like the main workspace. Same toast-timer fix as item 25.
31. `PipelineReplay.jsx` (Pipeline page) - the replay was fed the raw Python while Complexity/Run use `sanitizePythonCode`, so code with pasted non-breaking/zero-width spaces could show a "Fatal parse error / fallback" replay next to a normal Complexity result. It is sanitized the same way. The empty-state text no longer refers to the old "tab".
