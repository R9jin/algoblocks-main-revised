      "content": "The **0/1 Knapsack Problem** is one of the most famous applications of Dynamic Programming involving optimal selection under constraints.\n\n* Suppose a bag (knapsack) has a strict weight capacity.\n* You are given several items, each with a specific `weight` and a specific `value`.\n* The objective is to **maximize total value** without exceeding the bag's capacity.\n* Each item can only be selected once (either 0 or 1 instances), which is why it is called \"0/1\" Knapsack.\n\nThink of it like packing a suitcase for a trip. You have limited space measured by a weight limit. Each item provides a specific usefulness/value to you. You cannot take fractional items (you either pack your laptop or you don't), and you cannot take an item more than once.\n\nThis problem is fundamental in computer science because it strictly models constrained decision-making, where **Greedy Algorithms fail** and full Dynamic Programming 2D matrices are required."

      "content": "Let us define the problem with concrete variables:\n* **Capacity (`W`):** The absolute maximum weight the knapsack can hold (e.g., `4`).\n* **Items:** Each has a `weight` and a `value`.\n    * `Item A`: weight `1`, value `15`\n    * `Item B`: weight `3`, value `20`\n    * `Item C`: weight `4`, value `30`\n\nPossible Selections:\n* Take only `Item C`. Weight = 4. Value = **30**.\n* Take `Item B`. Weight = 3. Value = **20**.\n* Take `Item A` & `Item B`. Weight = `1 + 3 = 4`. Value = `15 + 20` = **35**.\n\nThe optimal solution is to take `A` and `B` for a value of 35. Notice that the best combination is *not* simply picking the single item with the highest value (`C=30`). You must evaluate combined sets."

      "id": "why-greedy-fails",
      "type": "deep_dive",
      "title": "Why Greedy Selection Fails",
      "content": "A common beginner instinct is to use a Greedy algorithm. You might try picking the highest value item first, or the item with the best value-to-weight ratio. **Greedy fails completely for 0/1 Knapsack.**\n\n* **Greedy by Highest Value:** If you pick `Item C` (Value=30, Weight=4), your remaining capacity is 0. Your final value is **30**. You missed the optimal `A+B` combo of **35**.\n* **Greedy by Ratio:** \n    * `Item C` ratio = 30/4 = 7.5\n    * `Item B` ratio = 20/3 = 6.66\n    * `Item A` ratio = 15/1 = 15\n    * Greedy by ratio picks `A` first (Weight=1, Cap=3 remaining). Next best ratio is `C` (doesn't fit). Next is `B` (Weight=3, Cap=0 remaining). In this specific instance ratio works, but it breaks easily on other datasets (e.g., if sizes prevent packing combinations cleanly).\n\nBecause items are discrete (0 or 1), greedy decisions trap the algorithm into wasting remaining capacity. DP solves this by safely tracking *all* possible optimal capacity utilization states."

    {
      "id": "core-dp-idea",
      "type": "concept",
      "title": "Core Dynamic Programming Idea",
      "content": "Dynamic Programming solves the Knapsack problem by generating solutions for smaller, hypothetical knapsacks (sub-capacities) and building up to the true capacity `W`.\n\n* **Overlapping Subproblems:** The optimal packing configuration for \"capacity 3 using only items A and B\" will be referenced multiple times when deciding whether to add item C.\n* **Optimal Substructure:** The optimal solution for capacity `W` using items `0..i` inherently relies on the optimal solution for capacity `W - weight[i]` using items `0..i-1`.\n\nInstead of branching out into `O(2^n)` subsets recursively, DP uses a 2D matrix to record the best possible value for *every capacity from 0 to W*, factoring in one item at a time."
    },
    {
      "id": "dp-matrix",
      "type": "deep_dive",
      "title": "Understanding the DP Matrix",
      "content": "The central structure in Knapsack DP is the **2D Matrix (`dp[i][w]`)**.\n\n* **Rows (`i`):** Represent the items being considered (from 0 to `n`).\n* **Columns (`w`):** Represent the hypothetical knapsack capacities (from 0 to `W`).\n* **Cell Value:** `dp[i][w]` stores the absolute maximum value achievable using a subset of the *first `i` items* strictly constrained to *capacity `w`*.\n\n**Base Cases:**\n* `Row 0` (0 items available) = 0 value. Nothing to pack.\n* `Column 0` (0 capacity available) = 0 value. Nothing fits.\n\nAs you evaluate row `i`, you introduce one new item to the system. You decide mathematically if including this new item is superior to excluding it. The final answer rests in the bottom-right corner: `dp[n][W]`."

    {
      "id": "cell-decisions",
      "type": "deep_dive",
      "title": "Decision-Making Per DP Cell",
      "content": "At every matrix cell `dp[i][w]`, the algorithm asks one binary question: **Include or Exclude the current item?**\n\n* **Option 1: Exclude.** We don't pack item `i`. The maximum value is simply whatever the best value was for the same capacity `w` using only the previous items `i-1`. \n    * Value = `dp[i-1][w]` (the cell directly above).\n* **Option 2: Include.** We pack item `i` (only allowed if `weight[i] <= w`). We gain `value[i]`, but we consume `weight[i]` capacity. We must add `value[i]` to the best optimal packing of the *remaining* capacity `w - weight[i]` using previous items.\n    * Value = `value[i] + dp[i-1][w - weight[i]]`.\n\nThe algorithm executes a pure `max()` check between Option 1 and Option 2."
    },
    {
      "id": "recurrence-relation",
      "type": "concept",
      "title": "Knapsack Recurrence Relation",
      "content": "The mathematical core of Knapsack Dynamic Programming is this recurrence relation:\n\n**If the item fits (`weight[i] <= w`):**\n`dp[i][w] = max(dp[i-1][w], value[i] + dp[i-1][w - weight[i]])`\n\n**If the item does NOT fit (`weight[i] > w`):**\n`dp[i][w] = dp[i-1][w]`\n\nThis recurrence drives the optimization process safely and reliably, comparing the \"skip it\" path against the \"take it\" path at every sub-capacity tier."

      "id": "step-by-step-example",
      "type": "deep_dive",
      "title": "Backtracking: Finding Which Items Were Selected",
      "content": "The bottom right cell `dp[n][W]` tells you the *maximum value*, but it doesn't immediately tell you *which items* you packed. To find the items, you trace back from `dp[n][W]`.\n\n1.  Start at `i = n, w = W`.\n2.  Compare `dp[i][w]` to the cell above it `dp[i-1][w]`.\n3.  **If they are the SAME:** Item `i` was NOT included. Move UP to `i = i-1`.\n4.  **If they are DIFFERENT:** Item `i` WAS included. Record Item `i`, subtract its weight from `w` (`w = w - weight[i]`), and move UP to `i = i-1`.\n5.  Repeat until `i == 0` or `w == 0`.\n\nFor our example matrix ending in `35`:\n* `dp[3][4] == 35`. Cell above `dp[2][4] == 35`. They match. Item C was skipped.\n* `dp[2][4] == 35`. Cell above `dp[1][4] == 15`. Different! Item B was packed. `w` becomes `4 - 3 = 1`.\n* `dp[1][1] == 15`. Cell above `dp[0][1] == 0`. Different! Item A was packed.\n* Packed Items: **A and B**."

      "content": "The algorithm processes the matrix using nested standard loops:\n\n1.  **Outer Loop:** Iterates over items `i` from `1` to `n`.\n2.  **Inner Loop:** Iterates over capacities `w` from `0` to `W`.\n3.  **Condition:** Check if `weight[i-1] <= w`.\n4.  **Max Logic:** Apply the recurrence relation to set `dp[i][w]`.\n\nThis simple `O(n * W)` loop guarantees that every required subproblem is solved before it is needed by a larger subproblem."

      "id": "why-knapsack-uses-dp",
      "type": "concept",
      "title": "Why Knapsack Strictly Requires DP",
      "content": "The Knapsack Problem sits mathematically right on the boundary where greedy techniques fail, forcing DP.\n\n* **Greedy fails:** Because items cannot be fractionally divided (you can't take 50% of a laptop), packing a high-value bulky item might leave small amounts of wasted, unfillable space.\n* **Overlapping Subproblems:** Computing the best loadout for \"15 pounds remaining\" happens repeatedly when testing different combinations of earlier items.\n* **Optimal Substructure:** The optimal 50-pound loadout containing a 10-pound item fundamentally relies on finding the perfect 40-pound loadout among the remaining items.\n\nDP evaluates *both* sides of the binary inclusion split (take it or leave it) and caches the results, completely shielding against greedy traps while avoiding exponential tree bloat."
